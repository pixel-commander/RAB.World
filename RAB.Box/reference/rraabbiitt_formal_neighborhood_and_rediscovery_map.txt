SECTION A — THE 22-ITEM FORMAL NEIGHBORHOOD
===================================================================

1. SYMBOLIC AI
   Explicit symbols, rules, relations.
   RRAABBIITT overlap:
     - Shape IDs
     - named seats
     - explicit relations
     - no requirement that meaning live in opaque vectors

2. CONSTRAINT SOLVING
   Candidate possibilities are eliminated by conditions until valid survivors remain.
   RRAABBIITT overlap:
     - 0 candidates -> unknown / stop
     - 1 candidate  -> may move
     - 2+ candidates -> ambiguous / stop
     - "no unique shape -> no execution"

3. TERM REWRITING
   Structures transform mechanically according to exact rules.
   RRAABBIITT overlap:
     SHAPE_A + RULE -> SHAPE_B

4. BOOLEAN LOGIC
   True / false, pass / fail, 1 / 0.
   RRAABBIITT overlap:
     STAMP(x) -> 1 | 0
   Important nuance:
     internal reasons for 0 can stay rich even if authority collapses to binary.

5. FINITE-STATE MACHINES / TRANSDUCERS
   State + input -> output + next state.
   RRAABBIITT overlap:
     T(state, input) -> state'
     one-turn workers
     explicit transitions
     no need for giant remembered conversation state

6. DYNAMIC SEMANTICS / DISCOURSE REPRESENTATION THEORY (DRT)
   Meaning updates a carried discourse context.
   RRAABBIITT overlap:
     BAG
     current referents
     current caller
     last object / action / relation

7. ANAPHORA / COREFERENCE RESOLUTION
   Resolve "it", "that", "this", etc. to prior referents.
   RRAABBIITT overlap:
     "can it do that?"
       it   -> current / last object
       that -> current / last action

8. ATTRIBUTE GRAMMARS
   Information can flow down from parents and back up from children.
   RRAABBIITT overlap:
     inherited idea / context down
     synthesized result up
     parent / child shape flow

9. TREE ZIPPERS
   Keep a focused subtree plus enough surrounding context to move up/down without rebuilding from root.
   RRAABBIITT overlap:
     current caller
     focus + surrounding bag
     moving through recursive structure without losing where you were

10. CONTINUATIONS
    Preserve "where the answer goes next."
    RRAABBIITT overlap:
      SEAT as return address
      ReturnTo = (ShapeID, SeatID)
      child can go arbitrarily deep and still return to the exact caller

11. BLACKBOARD SYSTEMS / DATAFLOW
    Independent workers contribute partial knowledge to shared state.
    RRAABBIITT overlap:
      cousins / dumbots
      partial results
      unresolved work can wait
      workers wake when relevant state changes

12. CORECursion / COALGEBRA
    Ongoing state evolution; not every process must shrink toward one terminal recursive base case.
    RRAABBIITT overlap:
      fractal can continue upward/downward
      output can become caller
      local branches can die while system continues

13. GRAPH REWRITING
    Local results can rewrite / expand the larger graph.
    RRAABBIITT overlap:
      returned shape can chisel or snowball the caller
      graph changes after local work returns

14. FORMAL CONCEPT ANALYSIS / CONCEPT LATTICES
    Objects x attributes, concept hierarchies, meets/joins.
    RRAABBIITT overlap:
      binary feature grids
      exact intersections
      concept structures
    Warning:
      combinations can explode.

15. MONTAGUE / COMPOSITIONAL SEMANTICS
    Natural-language meaning composed using typed functions and logic.
    RRAABBIITT overlap:
      F(x)
      typed seats
      output becomes valid input at the next scale

16. WORD2VEC / EMBEDDINGS
    Learned approximate vector geometry.
    RRAABBIITT use:
      discovery / scouting only
      NOT authority
    Rule:
      VECTOR = DISCOVERY
      MATH   = DECISION
      STAMP  = AUTHORITY

17. EXPLICIT FEATURE VECTORS / MULTI-HOT REPRESENTATIONS
    Named dimensions instead of opaque embedding dimensions.
    RRAABBIITT overlap:
      dog = {animal, adult, ...}
      puppy = {animal, young, ...}
      explicit seats are inspectable

18. SHAPE -> TOKEN ADDRESSING
    A token can be an exact address / handle for a whole known shape.
    RRAABBIITT overlap:
      TOKEN != meaning
      TOKEN = address
      SHAPE = meaning
      STAMP = authority

19. CLOSED VOCABULARY / ALLOWLIST INTELLIGENCE
    Unsupported concepts have no executable pathway.
    RRAABBIITT overlap:
      unknown != bad
      unknown -> no path -> 0
      preserve unknown position as a hole if structure matters

20. NEURO-SYMBOLIC / VERIFIER-GUIDED HYBRIDS
    Model proposes; exact system verifies.
    RRAABBIITT overlap:
      cloud can explore freely
      scripts / stamps decide what becomes real

21. RECURSIVE STAMPS / REFLECTION
    Verifiers can verify other verifiers.
    RRAABBIITT overlap:
      stamp that makes/checks stamps
      requires a tiny trusted root contract so verification terminates

22. SELF-ORIENTATION
    A system observes its own world and builds a current local model from sensors/audits.
    RRAABBIITT overlap:
      files
      imports
      exports
      calls
      paths
      hooks
      ownership
      repetition
      violations
      presence = registration
      deletion = gone
      TXT/source reality stays authoritative

THE SHAPE THAT HIT HARDEST
===================================================================

    λP.λQ.∀x(P(x) -> Q(x))

Token-ish reading:

    λP.      open / accept seat P
    λQ.      open / accept seat Q
    ∀x       for every x
    P(x)     test/apply P to x
    ->       if P(x), then Q(x) must hold
    Q(x)     test/apply Q to x

Fill:

    P = MAN
    Q = SING

Result:

    ∀x(MAN(x) -> SING(x))

The key RRAABBIITT connection:

    GENERAL SHAPE
    -> fill one seat
    -> returns a NEW CALLABLE SHAPE
    -> fill next seat
    -> resolved shape

That is partial application / currying territory.

THE ANTI-60-HOUR RULE
===================================================================

DO NOT STUDY WHOLE FIELDS.

When a mechanic appears:

    1. Describe the shape.
    2. Ask: "what is this already called?"
    3. Steal the exact mechanic.
    4. Build one tiny proof.
    5. Stop unless the proof exposes a real missing piece.

For the current Magic Box language experiment, learn only:

    λx.F(x)         function with seat x
    F(x)            apply
    P(x)            predicate / test
    P(x) -> Q(x)    implication
    ∀x              every x
    ∃x              some x exists

Then BUILD.

Do not disappear into the history of formal semantics unless one of those primitives
fails to solve a problem that actually exists.
