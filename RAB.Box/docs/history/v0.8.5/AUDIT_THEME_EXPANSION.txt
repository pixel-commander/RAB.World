THEME INSPECTOR
===============
inspect-theme composes existing Tools rather than rescanning independently. It chains:
  find-theme-tokens
  find-theme-variables
  find-class-names
  find-class-definitions
  find-component-definitions
  find-component-usage
  count-components
  count-class-usage
  count-component-usage
  count-theme-token-usage

It returns file/line evidence plus aggregate counts for tokens, classes, component declarations and component usage.

ENGINE LAW
==========
Public paths are semantic (audit/find/*, audit/count/*, audit/inspect/*).
Mechanical implementation lives behind a few shared private engines:
  tools/audit/_engines/line-pattern.mjs
  tools/audit/_engines/syntax.mjs
  tools/audit/_engines/metric.mjs
  tools/audit/_engines/structure.mjs
  tools/audit/_engines/theme.mjs

NOTES
=====
Some static scans are deliberately labeled candidates/heuristics rather than truths (for example floating promises, swallowed errors, deep nesting, magic numbers, and missing returns).
The package does not add an AST dependency. Public Tool addresses can keep their identity if a heuristic engine is later upgraded to AST-backed parsing.
