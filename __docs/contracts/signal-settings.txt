SIGNAL SETTINGS
===============

Signal and atom settings.json records use exactly these top-level fields:
id, name, title, description, type, date_created, date_modified, settings,
transmitting, signal.

ID and dates are positive numeric timestamps. settings is an array. signal
and transmitting are booleans; explicit false stays false. Type carries the
actual item type, such as action-atom. No meta, kind, indexed, path or project
name is required or emitted in the signal record. Paths belong to discovery
entries; project wording belongs in the category beacon prose.

makeSignalSettings/assertSignalSettings in RAB.Box/bridge/rab-node.mjs own
construction and validation. Tool House exposes createSignalSettings with
the existing shared numeric-ID allocator. Tool and runtime-node definitions
are separate contracts and retain their own metadata requirements.

Templates use null for ID and dates. Project stamping replaces those values
for each instance and validates adjacent contracts before writing. Source
beacons stay off and stamped beacons become on. Standalone signal and atom
creators use the same record builder. signal:false or transmitting:false
records are excluded by the updated signal index/search readers.
